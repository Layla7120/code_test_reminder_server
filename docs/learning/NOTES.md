# 교습 노트

## 사용자 선호

- **정직 > 인상적.** 과장된 표현, 하지 않은 일을 한 것처럼 쓰는 것을 싫어한다.
  잘한 것보다 틀린 것을 더 자세히 적는 게 이 사람의 문서 스타일이다(`docs/기록.md`).
- **측정 > 평가.** "괜찮아 보인다"가 아니라 숫자와 실행 결과를 원한다.
  검증 규칙은 산문이 아니라 빌드가 강제해야 한다(`verifyEndpointCoverage` 가 그 예).
- **단순화가 기준.** 복잡도를 더해 문제를 막는 대신 구조로 없애는 쪽을 고른다.
- 설명은 한국어. 코드 식별자는 원문 유지.
