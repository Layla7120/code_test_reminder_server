# Mission: 백엔드 설계 — 이 저장소를 교재로

## Why

백엔드 취업 준비. 이미 만든 서비스(코테독촉기)를 소재로 삼아, 남이 쓴 예제가 아니라
**내가 실제로 물린 결함**에서 개념을 역으로 배운다. AI 로 코딩하다 복잡도가 올라가
되돌린 경험이 있어서, "왜 이 복잡도가 필요 없었나"를 설명할 수 있는 상태가 목표다.

## Success looks like

- 면접에서 "왜 Redis 를 뺐나"에 측정값과 함께 답할 수 있다
- 스키마를 볼 때 식별성 → 사실 → 수명주기 → 불변조건 순으로 읽는다
- 파생 데이터를 만들 때 4문 테스트(원천·쓰기계약·소비자·드리프트 감지)를 반사적으로 돈다
- 테스트 경계를 어디에 둘지 근거를 대고 고른다

## Constraints

- 실사용자 없음 — 파괴적 변경이 지금은 싸다
- 의존성을 늘리지 않는다 (`AGENTS.md`)
- 검증은 실행 가능해야 한다. 산문 규칙은 반드시 새어나간다
- 문서가 코드와 어긋나면 문서 전체를 믿을 수 없게 된다

## Out of scope

- 인증/인가 (`permitAll` 유지)
- 분산 시스템·MSA — 단일 인스턴스 규모에서 벗어나지 않는다
- 프론트엔드
