# 포트의 위치가 곧 테스트 경계라는 것을 이해했다

사용자가 "포트가 무슨 말이냐"고 물어 처음부터 설명했다. 즉 포트/어댑터라는 용어 자체는
**새로 접한 상태**다 — 다음 세션에서 헥사고날/클린 아키텍처 용어를 전제로 두지 않는다.

다만 이 사람은 이미 관련 판단을 실무로 내려본 적이 있다. `MockGithubClient` 가 호출마다
새 UUID 를 sha 로 만들어 중복 수집 버그를 가렸던 사건을 직접 겪고 고쳤고, 그 교훈을
`AGENTS.md` §4 ("Mock 은 실물처럼 동작해야 한다")로 성문화해뒀다. **개념 이름은 없지만
현상은 이미 안다**는 상태라, 이름을 붙여주는 방식의 교습이 잘 맞는다.

## Implications

- 다음에 가르칠 후보: 테스트 더블의 종류(stub/mock/fake), 그리고 "이 테스트가 무엇을
  증명하는가"를 명시적으로 쓰는 습관 — 이 저장소의 테스트 표가 이미 그 형식이다.
- 아직 안 가르친 것: 의존성 역전, 어댑터가 여럿일 때의 구성. 필요해질 때까지 미룬다.
