# 남은 일

아카이브한 계획서에서 **착수하지 않은 것만** 옮겨 적은 목록. 경위는 링크를 따라간다.

| | 무엇 | 왜 안 했나 | 경위 |
|---|---|---|---|
| DB | `users.github_numeric_id` | GitHub 숫자 id 는 `GET /users/{login}` 을 더 불러야 얻는다. 그 호출을 어디 둘지가 미결 | [archive/PLAN-db-foundation.md](archive/PLAN-db-foundation.md) Phase 2 |
| DB | 타입 축소 (`score_month`·`sha` 의 `ascii_bin`, `commit_url` 폭, `DATETIME(6)` 정밀도) | 인덱스·행 크기 문제라 정합성과 무관. 측정과 같이 하는 게 맞다 | 같은 문서 Phase 4 |
| DB | CHECK 제약 | — | 같은 문서 Phase 5 |
| DB | 인덱스 재검토 + 측정 | — | 같은 문서 Phase 6 |
| 코드 | `findMemberCommits` (그룹 멤버 랭킹) | 유일하게 남은 매 요청 집계 경로 | [archive/PLAN-simplification.md](archive/PLAN-simplification.md) §범위 밖 |
| 테스트 | 테스트 컨테이너 static 싱글턴 전환 | 컨텍스트마다 컨테이너가 새로 뜬다 | 같은 문서 |
| 보안 | **레포 소유권을 확인하지 않는다** | `repositoryName` 은 가입 때 받은 문자열일 뿐이다. GitHub 이 404 만 안 내면 **공개 레포는 아무거나** 자기 것으로 등록해 커밋을 긁어올 수 있다. 인증을 붙여도 이건 따로 남는 문제다 — "로그인한 사람이 이 레포의 소유자인가"를 GitHub 에 물어야 한다 | — |
| 보안 | **요청자가 누구인지 확인하지 않는다** | `SecurityConfig` 가 `permitAll` 이고 `userId` 를 파라미터로 받는다. `DELETE /users/delete?userId=N` 한 줄로 남의 계정이 지워진다. Flask 원본과 같은 상태라 의도적으로 범위 밖에 뒀다 | README |
