# ADR-0008: 검증을 앵커와 게이트로 한다

**날짜** 2026-08-21 · **상태** 승인됨 · **관련** 전부

## 맥락

산문으로 적은 규칙은 새어나간다. 이 저장소는 그걸 한 번 겪고
`verifyEndpointCoverage` 를 만들었다 — 판정 근거가 사람이 읽고 센 값이 아니라
테스트 실행 중 **실제로 라우팅된 핸들러를 측정한** 값이다
(빌드가 남기는 build/endpoint-audit.txt — 산출물이라 백틱을 쓰지 않는다).

이번에 내린 결정들은 대부분 그 급의 장치가 없었다.

## 용어

> **앵커** — 기계가 참·거짓을 판정할 수 있는 사실 하나.
> "잘 되어 있다"가 아니라 `information_schema.REFERENTIAL_CONSTRAINTS.DELETE_RULE = 'CASCADE'`.
>
> **게이트** — 앵커가 거짓이면 **빌드를 깨는** 장치. 사람이 읽고 판단하지 않는다.

## 검토하고 버린 것

### 스키마 앵커를 마이그레이션 SQL 파싱으로

**동어반복이라 버렸다.** Flyway 가 그 SQL 을 실행해 DB 를 만들었으니 항상 통과한다.
아무것도 증명하지 못한다.

이 지점에서 개념이 하나 갈린다 — **표가 세 종류이고 성격이 다르다.**

| | 무엇 | 진실 원천인가 | 어긋나면 |
|---|---|---|---|
| DDL (`V*.sql`) | 실제로 DB 를 만드는 것 | ✅ **원천** | — |
| 테스트의 기대값 표 | 사람이 진술한 **의도** | ❌ 원천도 사본도 아님 | **빌드가 깨진다 = 목적** |
| 문서의 표 (README ERD) | 원천에서 손으로 옮긴 것 | ❌ **파생 사본** | 아무 일도 안 일어난다 |

두 번째가 핵심이다. **테스트의 기대값 표는 파생 사본이 아니라 독립적인 제2진술이다.**
사본이면 하나여야 하지만 독립 진술은 **둘이어야 의미가 있다** — 어긋남 자체가 정보다.

`participate.user_id` 가 RESTRICT 인 건 의도적 선택인데, 마이그레이션 파일만 보면
`ON DELETE` 절이 없는 것처럼 보인다 — **빠뜨린 것과 구별이 안 된다.**
테스트가 그걸 진술하면, 나중에 누가 편의로 CASCADE 를 걸 때 빨간불이 나고 이유가 적혀 있다.

*진실 원천이 하나여야 한다는 건 파생 사본에 대한 규칙이지, 의도를 진술하는 곳에 대한
규칙이 아니다.*

### 게이트를 별도 Gradle 태스크로

`verifyEndpointCoverage` 가 태스크인 건 **테스트 실행의 부산물**을 읽어야 해서다 —
테스트가 다 끝나야 판정이 가능하다. 스키마 앵커는 그런 순서 의존이 없다.
Testcontainers 로 뜬 MySQL 에 쿼리 한 번이면 된다.

### detekt 도입 — 확인 결과 추천이 뒤집혔다

**측정으로 죽은 코드 4건을 찾았다** (전부 호출 0회 확인):

| 대상 | 상태 |
|---|---|
| `CommitRepository.existsBySha` | 호출 0회. **게다가 의미가 틀렸다** — `4ee76dc` 가 sha 유일성을 `(user_id, sha)` 로 좁혔는데 이 함수는 전역 sha 로 조회한다. 살아 있었다면 **남의 커밋에 `true` 를 반환**한다 |
| `GroupRepository.findByGroupName` | 호출 0회 |
| `UserRepository.findByNickname` | 호출 0회 |
| `RankProjection.kt` | **파일명이 가리키는 `RankProjection` 인터페이스가 파일 안에 없다.** Phase 4 가 그 타입을 지우면서 파일명만 남았다 |

detekt 문서를 확인한 결과 미사용 코드 규칙은
`UnusedPrivateFunction`·`UnusedPrivateClass`·`UnusedPrivateProperty` 로 **전부 private 전용**이고,
공개 함수·인터페이스 메서드는 대상이 아니다. **위 4건 중 3건은 Spring Data 리포지토리의
공개 인터페이스 메서드라 detekt 를 도입해도 안 잡힌다.** grep 10줄이 잡은 것을.

추가로 detekt 는 baseline 파일을 만드는데, 그게 `endpoint-allowlist.txt` 처럼
*"부채 명세서지 예외 처리가 아니다"* 라고 매번 설명해야 하는 두 번째 파일이 된다.

### 순환복잡도·함수 길이 게이트

**이 저장소에서 물린 적이 없다.** 장치를 추가하는 기준은 *"실제로 물린 적이 있는가"* 이고
(`verifyEndpointCoverage` 는 "테스트 35개 초록불, 버그 6개" 뒤에 생겼다),
죽은 코드는 그 기준을 통과하지만 복잡도 지표는 통과하지 못한다.

게다가 **거짓 양성을 낸다.** 측정상 최장 함수는 `fetchAndSaveCommits` 44행인데
**그중 24행이 주석**이라 실제 코드는 20행이다. 함수 길이를 게이트로 걸면 이 파일이
걸리는데 문제가 아니다.

### 주석/코드 비율 상한 게이트

버린 이유: **지표가 목표가 되면 게임이 된다** — 비율을 맞추려고 쓸모 있는 주석을 지운다.
그리고 `GithubClientPort.kt`(코드 5행/주석 9행 = 180%)는 포트 인터페이스라 설명이 조밀한 게
정상인데 최악 점수를 받는다. **거짓 양성이 가장 심한 지표다.**

### 파일명 = 주 타입명 게이트

버린 이유: Kotlin 은 한 파일에 타입 여럿을 두는 게 정상 관용구다(`Exceptions.kt` 가 그렇다).
"주 타입"의 정의부터 애매하고, 얻는 건 이름의 미관뿐이다 —
**틀린 파일명이 잘못된 동작을 만든 적은 없다.** `existsBySha` 와 대비된다.
`RankProjection.kt` 는 이번에 `Projections.kt` 로 고치고 게이트는 만들지 않는다.

*검토했고 안 만들기로 했다는 것과 생각 안 해봤다는 것은 다르므로 여기 적는다.*

## 문서의 숫자

측정 결과 **문서 숫자가 이미 세 갈래로 갈렸다** — `docs/기록.md` "테스트 74개",
`README.md` "81개 통과", 실제 `@Test` **97개**.

기준은 *"그 숫자를 기계가 이미 지키고 있는가"* 다.

| 숫자 | 판정 |
|---|---|
| "테스트 81개" (README) | ❌ **뺀다.** CI 배지가 이미 증명한다 |
| "미도달 6개" (`AGENTS.md`·allowlist) | ✅ **남긴다.** 그 파일 자체가 게이트라 틀리면 빌드가 깨진다 |
| "50k 기준 87ms → 0.5ms" | ✅ **남긴다. 단 측정 시점을 병기한다** |

세 번째가 중요하다. **측정값은 낡는 게 아니라 그 시점의 사실**이라 남겨야 한다 —
`docs/기록.md` 가 같은 스크립트로 세 번 재서 절대값이 2배 달랐던 것을 기록해둔 것과 같은
이유다. 지금 README 의 `87ms → 0.5ms` 에는 날짜가 없다. **새 규칙: 측정값에는 시점을 붙인다.**

**생성 스크립트를 두고 문서에 붙여넣는 방식**은 버렸다. "붙여넣는다"에서 사람이 다시
개입하므로 낡을 수 있는 숫자가 여전히 문서에 남는다 — 문제를 한 칸 미룰 뿐이다.

## README ERD

README 의 `erDiagram` 은 컬럼·제약·주석까지 손으로 옮긴 **스키마의 파생 사본**이고,
이번 작업이 정확히 그걸 낡게 만든다(`active` 제거, `history` 컬럼 3개 변경, FK 정책 추가).
백틱 게이트는 식별자만 보므로 **표 내용의 드리프트는 못 잡는다.**

**해상도를 낮춘다** — 엔티티와 관계만 남기고 컬럼 목록은 뺀다.
원리는 하나다: **드리프트 확률이 높은 부분만 걷어낸다.** 관계는 거의 안 바뀌고 컬럼은 자주
바뀐다. 컬럼을 빼면 그 표는 **게이트 없이도 안 낡는다.**

*마이그레이션에서 ERD 를 생성하는 방식*은 버렸다 — 아무도 안 돌리는 스크립트가 되기 쉽고,
생성된 ERD 는 *"`member_counter` 는 `participate` 에서 파생"* 같은 **설명**을 담지 못한다.
그게 지금 README ERD 의 진짜 값어치다. 그 설명들은 없애지 않고 바로 아래
"진실 원천과 파생" 표로 옮긴다 — 그 표는 컬럼 목록이 아니라 **관계에 대한 진술**이라 잘 안 낡는다.

## 게이트가 요구하는 표기 규약

게이트를 실제로 돌려보고 나온 것이다. 프로토타입: `scripts/check-doc-refs.sh`

**① 백틱은 "지금 실재하는 것"만 감싼다.**
없어진 것을 가리킬 때는 백틱을 쓰지 않는다. README 가 `` `infra/init.sql` `` 이라고
적고 있었는데 그 파일은 Phase 0 에서 삭제됐다 — 과거를 서술하는 정확한 문장이지만,
백틱이 붙는 순간 게이트에게는 "실재 주장"이 된다. `구 infra/init.sql 을` 로 고쳤다.

**② ADR 은 구현되기 전까지 `승인됨(미구현)` 이다.**
ADR 의 "어떻게 지켜지나" 절은 대개 **아직 없는 테스트**를 가리킨다.
게이트는 미구현 ADR 과 `PLAN-*.md` 의 식별자 검사를 건너뛰고, 구현이 끝나 상태가
`승인됨` 으로 바뀌면 그때부터 검사한다.

**상태를 바꾸는 행위 자체가 게이트에 걸린다** — 게이트가 없는 ADR 을 `승인됨` 으로
표시하면 빨간불이 난다. *"결정했다"* 와 *"했다"* 를 문서가 구별하게 만드는 장치다.

**③ 마크다운 링크는 층과 무관하게 전부 검사한다.**
깨진 링크는 언제나 결함이다. 실제로 `PLAN-aggregate-table.md` 를 아카이브로 옮기면서
구 docs/삭제-명세.md 의 링크가 깨졌고, 게이트가 그 자리에서 잡았다.

### 알려진 한계

- `/` 없는 파일명(`` `init.sql` ``)은 검사하지 않는다. 오탐이 많아져서다
- "완료된 계획이 루트에 남아 있는가"는 판정 못 한다 → [ADR-0007](0007-문서를-시제로-세-층으로-나눈다.md)
- 문서 **표의 내용**(컬럼 타입 등)은 검사 못 한다. 그래서 README ERD 의 해상도를 낮춘다

## 게이트의 자기 제한

게이트는 공짜가 아니다. 이 저장소는 `endpoint-allowlist.txt` 를 두면서
*"부채 명세서지 예외 처리가 아니다"* 라고 못 박아야 했다.

**규칙: 오탐이 늘면 규칙을 넓히지 말고 게이트를 지운다.**

특히 죽은 코드 스크립트는 오탐이 난다 — 프레임워크가 호출하는 것
(`@Bean`, `@ExceptionHandler`, 컨트롤러 핸들러, JPA projection getter)은 소스에 호출부가 없다.
백틱 게이트도 판정 대상을 세 종류로 한정한다: ① 대문자로 시작하고 `Test` 로 끝나는 이름
② `/` 를 포함하는 파일 경로 ③ `uk_`·`fk_`·`idx_` 접두 식별자.
SQL 키워드나 설명용 의사코드까지 훑으면 오탐이 쏟아진다.
