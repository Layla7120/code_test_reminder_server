# ADR-0009: 주석은 이 파일의 코드를 설명할 때만 남긴다

**날짜** 2026-08-21 · **상태** 승인됨 · **관련** [0007](0007-문서를-시제로-세-층으로-나눈다.md), [0008](0008-검증을-앵커와-게이트로-한다.md), `AGENTS.md`

## 맥락

이 저장소는 의도적으로 **경위**를 주석에 적어왔다(`// 경위: docs/기록.md`).
`5ff74b1` 에서 한 번 축약했는데도 측정 결과 `main` 의 주석/코드 비율이 **23%** 다.

파일별로 보면 편차가 크다:

```
GithubClientPort.kt    코드   5 / 주석  9   180%
ServiceZone.kt         코드  18 / 주석 20   111%
GroupRepository.kt     코드  21 / 주석 17    80%
RankService.kt         코드  25 / 주석 19    76%
MockGithubClient.kt    코드  39 / 주석 22    56%
UserService.kt         코드  53 / 주석 26    49%
```

**중요한 변화가 있다.** 지금까지 경위가 갈 곳이 주석밖에 없었는데,
[ADR-0007](0007-문서를-시제로-세-층으로-나눈다.md) 로 **ADR 층이 생겼다.**

## 처음 낸 안과 그것이 철회된 이유

처음에는 두 범주로 나누자고 했다 — *"이 코드가 왜 이상해 보이는가"* 는 코드에,
*"무엇을 검토하고 왜 이걸 택했나"* 는 ADR 에.

**사용자가 철회시켰다**: 매번 두 범주를 판정하게 만드는 규칙은 새 에이전트가
일관되게 적용할 수 없다. 그리고 *"이 규칙조차 문서에 적어놓는 건가"* —
**규칙을 늘려서 규칙 준수 문제를 푸는 건 순환이다.**

맞는 지적이다. 다만 한 가지는 구분해야 한다. `AGENTS.md` 는 보통 문서가 아니라
**에이전트 컨텍스트에 자동으로 실린다.** 그래서 실패 모드가 "못 본다"가 아니라
**"양이 많아 일관되게 못 지킨다"** 다. 지금 8개 규칙이고, 9번째가 한계일 수 있다.

## 결정

**판정 질문 하나.**

> **이 주석이 설명하는 코드가 이 파일에 있는가? 없으면 ADR 로.**

두 범주가 아니라 예/아니오 한 번이고, **답이 파일 안에 있어 판단이 필요 없다.**

남는다 — 바로 아래 줄을 설명한다:
```kotlin
// 다시 읽는다. leaveGroup 의 decrementMemberCounter 가 clearAutomatically 라
// 영속성 컨텍스트를 통째로 비우고, 위 user 는 준영속이 되어 변경이 반영되지 않는다.
getUser(userId).deactivate()
```

옮긴다 — **설명하는 코드가 여기 없다**:
```kotlin
// CommitService.kt — "없어진 Redis 락"을 9줄에 걸쳐 설명. 그 락은 여기 없다.
// UserService.kt  — "예전에는 active=false 와 점수 행 삭제만 했다". 그 코드는 없다.
```

## 함께 결정: `AGENTS.md` 를 늘리지 않고 줄인다

**게이트가 있는 규칙은 한 줄로 줄이고, 경위는 ADR·회고로 링크한다.**

지금 규칙 1(HTTP 계층 테스트)은 약 20행인데 절반이 *"왜 이 규칙이 있는가"* 설명이다.
**그런데 그 규칙에는 이미 게이트가 있다**(`verifyEndpointCoverage`).
안 지키면 빌드가 깨지므로 **문서가 설득할 필요가 없다.**

> HTTP 테스트 없이 엔드포인트 추가 불가. 게이트: `verifyEndpointCoverage`.
> 경위: `docs/기록.md`

이렇게 하면 `AGENTS.md` 가 **줄어들면서** 주석 규칙이 들어간다. 순 증가가 없다.

**정직한 약점**: 그 이야기들("테스트 35개가 초록불인데 버그 6개였다")에는 규칙을
*납득시키는* 힘이 있다. 링크를 따라가지 않는 사람에게는 규칙이 근거 없는 명령으로 보인다.
다만 **게이트가 있는 규칙은 납득이 필요 없다** — 안 지키면 못 넘어간다.
납득이 필요한 건 게이트 없는 규칙들이고, **그건 길게 남긴다.**

## 검토하고 버린 것

**규칙 없음, 게이트만.**
진지한 후보였다 — 규칙 0개가 규칙 1개보다 확실히 잘 지켜진다.
버린 이유: 게이트만 두면 *"없어진 락 설명 9줄"* 이 안 잡힌다.
그 주석에 나오는 이름(`SETNX`, `TTL`)은 실재 여부를 판정할 대상이 아니다.

**주석/코드 비율 상한 게이트.**
→ [ADR-0008](0008-검증을-앵커와-게이트로-한다.md) 에 근거 기록.
지표가 목표가 되면 게임이 되고, `GithubClientPort.kt` 처럼 조밀한 게 정상인 파일이
최악 점수를 받는다.

## 결과

- `RankService.kt`(76%)·`UserService.kt`(49%) 의 주석 대부분이 Redis·`active` 경위라
  **이번 작업으로 자연히 사라진다.** 주석을 줄이려고 지우는 게 아니라
  **설명 대상이 없어져서** 지우는 것이다.
- **잃는 것**: 경위를 읽으려면 파일을 옮겨 가야 한다. 그래서 함정 주석
  (위 `deactivate()` 예)은 **코드에 남긴다** — 함정을 밟기 직전에 파일을 옮겨 읽게 하는
  마찰이 정확히 사고가 나는 자리다.
- **잃는 것**: 이 규칙 자체는 게이트가 없다. 사람이 지킨다.

## 어떻게 지켜지나

규칙은 사람이 지키고, **참조 무결성은 기계가 지킨다.**

[ADR-0008](0008-검증을-앵커와-게이트로-한다.md) 의 백틱 게이트를 **`.kt` 주석까지** 넓힌다.
지금 소스 주석에 `docs/기록.md`, `PLAN-aggregate-table.md Phase 4`,
`GroupJoinConcurrencyTest` 같은 참조가 박혀 있고, 이번 작업이 그중 일부를 무효화한다
(`PLAN-aggregate-table.md` 는 `docs/archive/` 로 이동).

**컴파일러는 이걸 전혀 안 잡는다** — 주석이니까.
`docs/기록.md` 를 가리키는 주석이 여러 곳 있는데, 그 파일이 옮겨지거나 이름이 바뀌면
전부 조용히 거짓이 된다.
