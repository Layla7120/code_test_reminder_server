# ADR-0010: 난이도는 출처별 축으로 보존하고 환산하지 않는다

**날짜** 2026-08-21 · **상태** 승인됨 · **관련** [0003](0003-github-커밋을-전체-이력으로-수집한다.md), [0008](0008-검증을-앵커와-게이트로-한다.md)

## 맥락

[ADR-0003](0003-github-커밋을-전체-이력으로-수집한다.md) 으로 전체 이력을 수집하게 되면서
실제 저장소(`layla7120/Algorithms`)의 커밋을 **처음으로 다 받아봤다.**
191건 중 패턴에 맞은 188건의 대괄호 값을 센 결과 (2026-08-21):

| 출처 | 표기 | 건수 |
|---|---|---:|
| 백준 | `Gold IV`, `Silver I` … | 92 |
| 프로그래머스 | `level 1` ~ `level 4` | **87** |
| SWEA | `D3`, `D4` | **9** |

`CommitLevel.from` 은 백준 티어만 알았다. **96건(51%)이 `UNRATED` 로 뭉쳐 있었다.**

몰라서 생긴 일이 아니다. 코드 주석이 이렇게 적혀 있었다 —
*"매핑 실패(`"level 1"` 등 비BOJ 포맷) → UNRATED로 저장 (커밋 자체는 유효)"*.
**이름으로 알고 있으면서 삼키는 쪽을 골랐다.**

왜 안 보였나. 랭킹 점수는 `COUNT(*)` 라 난이도를 쓰지 않는다. 커밋은 정상 저장되고
개수도 맞는다. 틀리는 곳이 `GET /commits/level` 하나뿐이라 **증상이 화면 한 칸에만
갇혀 있었다.** 30건 절단(ADR-0003)과 같은 종류다 — 틀렸다는 사실이 안 보이는 결함.

## 결정

세 사이트를 **각자의 축으로 보존한다. 서로 환산하지 않는다.**

`CommitLevel` 에 프로그래머스 `LEVEL0`~`LEVEL5` 와 SWEA `D1`~`D6` 을 넣는다.
백준 티어는 그대로 두고 티어 번호는 계속 버린다(`Gold IV` → `GOLD`).
세 축 어디에도 안 맞는 표기는 `UNRATED` 로 남는다.

## 검토하고 버린 것

**환산표를 정해 백준 티어로 흡수 (`level 2` → `SILVER` 식).**
버린 이유: **환산은 사실이 아니라 의견이다.** 사이트마다 채점 기준과 문제 분포가 달라
`level 2` 가 `Silver` 인지 `Gold` 인지 정할 근거가 이 저장소에 없다. 더 나쁜 건
되돌릴 수 없다는 것이다 — 원본 표기를 버리고 의견을 저장하면, 나중에 환산표를 고쳐도
이미 저장된 행은 못 고친다. 진실 원천을 의견으로 덮어쓰는 꼴이다(`docs/용어집.md`).

**대괄호 값을 문자열 그대로 저장 (`"Gold IV"` 그대로).**
버린 이유: 티어 번호까지 살아나지만 집계 키가 무한대가 된다. 오타 하나가 새 난이도가
되고, `GET /commits/level` 의 응답 키를 아무도 예측할 수 없게 된다. enum 이 하던
"알려진 값의 목록"이라는 일이 사라진다.

**아무것도 안 한다 (`UNRATED` 유지).**
버린 이유: 측정하기 전에는 이게 얼마나 큰지 몰랐다. **96건, 절반이다.**
"비BOJ 포맷은 드물다"는 암묵적 전제 위에 서 있던 선택인데, 전제가 틀렸다.

## 결과

- `GET /commits/level` 의 응답 키가 는다. 최대 7종 → 19종.
  **프런트는 세 축을 한 줄로 세울 수 없다** — 출처별로 나눠 그려야 한다.
  이게 이 결정이 프런트에 떠넘기는 비용이고, 환산을 골랐다면 안 냈을 비용이다.
- 랭킹·점수·순위는 **영향 없다.** `COUNT(*)` 라 난이도를 안 쓴다.
- 스키마 변경 없다. `commits.level` 이 `VARCHAR(20)` 이고 새 값 중 가장 긴 게
  `LEVEL0`(6자)이라 그대로 들어간다.
- **잃는 것 ①**: **이미 저장된 행은 안 고쳐진다.** `commits.level` 이 `updatable = false`
  이고 bulk upsert 가 `ON DUPLICATE KEY UPDATE sha = sha` 라, 재수집해도 기존 96행은
  `UNRATED` 로 남는다. 고치려면 지우고 다시 받아야 한다.
- **잃는 것 ②**: 관측 범위 밖까지 넣었다. 실물로 본 건 `level 1`~`level 4` 와 `D3`·`D4`
  뿐인데 `LEVEL0`·`LEVEL5`·`D1`·`D2`·`D5`·`D6` 도 넣었다. **각 사이트의 문서상 범위를
  따른 것이고 실측이 아니다.** 넣은 이유는 범위를 좁게 잡는 게 곧 조용한 절단이라서다 —
  ADR-0003 이 상한을 버린 것과 같은 이유다. 틀렸다면 줄이면 된다.
- **아직 안 정한 것**: 기존 `UNRATED` 행을 백필할 것인가. 실사용자가 없어 지금은
  지우고 다시 받으면 되지만, 사용자가 생긴 뒤에는 답이 달라진다.

## 어떻게 지켜지나

`CommitLevelTest` — 세 사이트 표기와 흔들림(대소문자·공백·`Lv.`)을 고정하고,
**위 실측 21종 188건이 그대로 재현되는지**를 앵커로 둔다. "잘 되게 고쳤다"가 아니라
그때 그 입력에서 이 표가 나오는가를 묻는다. → [ADR-0008](0008-검증을-앵커와-게이트로-한다.md)

같은지를 HTTP 로 고정한다. `endpoint-allowlist.txt` 에서 이 엔드포인트를 지웠다.
