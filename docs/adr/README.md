# ADR — 아키텍처 결정 기록

한 파일에 결정 하나. **왜 그렇게 정했나**와 **무엇을 검토하고 버렸나**를 시점과 함께 남긴다.

## 이 디렉터리가 있는 이유

결정의 경위를 코드 주석·계획서·커밋 메시지에 나눠 적어와서 만들었다.
명세서는 **지금 규칙이 무엇인가**를, ADR 은 **왜 그 규칙인가**를 말한다.
둘을 한 파일에 두면 개정할 때 경위가 같이 덮어써진다.

## 문서 층위 (→ [ADR-0007](0007-문서를-시제로-세-층으로-나눈다.md))

| 층 | 시제 | 어디 | 백틱 게이트 |
|---|---|---|---|
| 명세 · ADR · README · AGENTS.md | **현재** | `docs/`, 루트 | ✅ 검사 |
| 진행 중인 계획 | 미래 | 루트 `PLAN-*.md` | ✅ 검사 |
| 회고 · 완료된 계획 | **과거** | `docs/기록.md`, `docs/archive/` | ❌ 제외 |

과거 층은 그 시점의 사실을 적은 것이라 현재 코드와 어긋나는 게 정상이다.

## 형식

```md
# ADR-NNNN: 제목

**날짜** · **상태**(승인됨 | 대체됨 by ADR-NNNN) · **관련**

## 맥락
왜 이 결정이 필요했나. 측정값이 있으면 여기.

## 결정
무엇으로 정했나.

## 검토하고 버린 것
대안마다 왜 버렸는지. **이 절이 ADR 의 값어치다.**

## 결과
얻는 것과 **잃는 것**. 잃는 것을 안 적으면 이 문서를 믿을 수 없다.

## 어떻게 지켜지나
게이트가 있으면 그 이름. 없으면 "없음"이라고 적는다.
```
