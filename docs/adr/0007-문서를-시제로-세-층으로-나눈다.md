# ADR-0007: 문서를 시제로 세 층으로 나눈다

**날짜** 2026-08-21 · **상태** 승인됨(미구현) · **관련** [0008](0008-검증을-앵커와-게이트로-한다.md), [0009](0009-주석은-이-파일의-코드를-설명할-때만-남긴다.md)

## 맥락

문서가 일관돼 있지 않다는 것이 출발점이었다. 원인은 개수가 아니라
**한 파일이 여러 역할을 겸한다**는 것이다.

| 파일 | 겸하고 있던 역할 |
|---|---|
| `PLAN-aggregate-table.md` (549줄) | **전부 완료.** 그런데 루트에 있어 현재 계획처럼 보임 |
| `PLAN-db-foundation.md` (380줄) | 계획 + 진행기록 + 결정근거 + 폐기된 Phase |
| `docs/삭제-명세.md` (164줄) | 명세인데 §6 에 미결정을 담아 계획서도 겸함 |
| `docs/기록.md` | 회고. **사용자 소유, 손대지 않음** |

"지금 규칙이 무엇인가"와 "무엇을 할 것인가"와 "왜 그렇게 정했나"가 섞여 있어,
어느 문장이 현재 진실인지 **읽는 사람이 판단해야** 했다.

## 결정

**시제로 나눈다.**

| 층 | 시제 | 어디 | 백틱 게이트 |
|---|---|---|---|
| 명세 · ADR · README · `AGENTS.md` | **현재** | `docs/`, 루트 | ✅ 검사 |
| 진행 중인 계획 | 미래 | 루트 `PLAN-*.md` | ✅ 검사 |
| 회고 · 완료된 계획 | **과거** | `docs/기록.md`, `docs/archive/` | ❌ 제외 |

**규칙 한 문장: 완료된 계획은 루트에 남지 않는다.**

`PLAN-aggregate-table.md` 는 `docs/archive/` 로 옮긴다.
`docs/기록.md` 는 사용자 소유이므로 이 정리에서 제외한다.

## 검토하고 버린 것

**계획서를 없애고 ADR + 명세 2층으로.**
버린 이유: `PLAN-db-foundation.md` 의 값어치가 **"무엇을 왜 그 순서로"** 에 있다
(§2 의 7단계 결정 순서, Phase 간 의존성). ADR 은 결정 하나 단위라 순서와 의존성을
담기에 나쁘다. 옮기면 그 내용이 증발한다.

**그대로 두고 이번 결정만 반영.**
버린 이유: 다음번에 같은 문제가 그대로 반복된다.

## 결과 — 이 층 구분이 게이트의 범위 규칙이 된다

이게 예상 못 한 이득이었다. 문서 백틱 게이트
([ADR-0008](0008-검증을-앵커와-게이트로-한다.md))를 지금 걸면 **8곳이 깨진다**:

```
docs/기록.md             → CommitFetchLockReleaseTest, RankingScoreHealTest,
                           RankingSelfHealingSchedulerTest, RankPathConsistencyTest,
                           RankServiceFallbackTest                          (5)
PLAN-aggregate-table.md  → CommitFetchLockReleaseTest, RankPathConsistencyTest,
                           RankServiceFallbackTest                          (3)
```

**그런데 이 문서들이 틀린 게 아니다.** 회고는 과거 시점의 사실을 적은 것이고,
Phase 4 에서 지운 테스트를 "그때 이런 게 있었다"고 쓰는 건 정확한 서술이다.
**현재 코드와 어긋나는 게 정상이다.**

시제로 나누면 예외 목록이 필요 없다 — **디렉터리 위치 하나가 게이트 여부를 결정**하고,
새 문서를 어디 둘지 정하는 순간 그것도 같이 정해진다. 그리고 위 8건은
`PLAN-aggregate-table.md` 아카이브 이동(3건) + 회고 제외(5건)로 **첫날부터 초록불**이다.

**잃는 것**: `docs/archive/` 의 문서는 검사받지 않으므로 시간이 지나면 더 낡는다.
그게 의도다. 다만 **아카이브에서 무언가를 다시 꺼내 쓸 때는 검사 대상이 된다**는 것을
기억해야 한다.

## 어떻게 지켜지나

부분적으로만 지켜진다. **"완료"의 판정 기준을 기계가 못 만든다** —
루트에 완료된 계획이 남아 있는지는 사람이 봐야 한다.
게이트가 커버하는 건 백틱 식별자의 실재 여부뿐이다.
이 한계를 적어두는 것이 이 절의 목적이다.
