# ADR-0004: 페이지네이션 루프를 포트 아래 두고 HTTP 를 가짜로 만든다

**날짜** 2026-08-21 · **상태** 승인됨(미구현) · **관련** [0003](0003-github-커밋을-전체-이력으로-수집한다.md), `docs/learning/lessons/0001-port-and-pagination.html`

## 맥락

[ADR-0003](0003-github-커밋을-전체-이력으로-수집한다.md) 이 페이지네이션 루프를 만든다.
그 루프의 전부는 **종료 조건**이고, 틀리는 방식이 둘이다.

| 틀린 방식 | 증상 | 알아챌 수 있나 |
|---|---|---|
| 영영 안 멈춤 | 무한 루프, rate limit 소진 | 즉시 안다 |
| 너무 일찍 멈춤 | 커밋이 조용히 누락 | **아무도 모른다** |

문제는 이 루프를 **어디에 두느냐가 곧 테스트 가능한가를 결정한다**는 것이다.

`GithubClientPort` 는 인터페이스이고 구현이 둘이다 — 실물 `GithubClient` 와
`MockGithubClient`. Mock 은 부하 테스트 전용이 아니라 **실제 테스트 3개**
(`CommitFetchApiTest`, `CommitDuplicateFetchTest`, `MockGithubClientTest`)가 쓴다.

포트 시그니처에 `page` 가 없으므로, 루프를 어댑터 안에 두면 **Mock 을 끼우는 순간
루프를 통째로 건너뛴다.** 종료 조건을 반대로 써도 빌드는 초록불이다.
`AGENTS.md` §2 — *"지웠을 때 아무 테스트도 안 깨지는 코드는 검증되고 있지 않은 것"* — 에 걸린다.

## 결정

루프는 `GithubClient`(포트 아래)에 두고, **`GithubClient` 자체를 HTTP 레벨에서 테스트한다.**
`RestClient` 를 생성자에서 직접 만들지 않고 `RestClient.Builder` 를 주입받도록 바꾼다.

```
CommitService ──▶ GithubClientPort
                       └── GithubClient ⟳ ──▶ MockRestServiceServer
```

테스트 경계를 포트가 아니라 **소켓으로 한 칸 내린다.**

## 검토하고 버린 것

**포트 위 — 포트가 `page` 를 받고 `CommitService` 가 루프.**
루프는 검증되지만 `CommitService` 가 "GitHub 은 100건씩 준다"를 알게 된다.
외부 API 세부를 격리하려고 포트를 둔 것인데 그 목적을 깎는다.

**포트 아래 + 테스트 없음.**
버린 이유: 위 `AGENTS.md` §2 위반. 이 저장소가 실제로 물린 적이 있다 —
`MockGithubClient` 가 호출마다 새 UUID 를 sha 로 만들던 시절, 중복 수집 버그가
부하 테스트를 통과했다(`AGENTS.md` §4, `docs/기록.md` ②).

**WireMock / OkHttp MockWebServer.**
버린 이유: **의존성이 는다.** `AGENTS.md` §스택 — *"새 라이브러리가 필요해 보이면
먼저 현재 classpath 를 확인한다."*

## 결과

**확인한 사실 (2026-08-21):**

- `MockRestServiceServer.bindTo(RestClient.Builder)` 는 Spring Framework **6.1** 부터 존재하고
  현재 deprecated 가 아니다 (javadoc 확인)
- `./gradlew dependencies --configuration testRuntimeClasspath` 결과
  **`org.springframework:spring-test:7.0.6` 이 이미 있다.** 의존성은 늘지 않는다

**정직하게 남길 단서:** Spring 공식 레퍼런스는 *"MockRestServiceServer 는 mock web server 가
나오기 전에 만들어졌다. 지금은 전송 계층과 네트워크 조건까지 보려면 mock web server 를
권장한다"* 고 적어뒀다. **여기서 이걸 고르는 건 Spring 의 권장안이라서가 아니라,
검증 대상이 전송 계층이 아니라 루프 종료 조건이고 대안은 의존성이 늘기 때문이다.**
이 문장을 빼면 이 ADR 이 권위를 참칭하게 된다.

**잃는 것**: `GithubClient` 의 생성자가 바뀐다. 지금은 `@Value` 로 토큰만 받는데
`RestClient.Builder` 도 받게 된다. 실제 배선은 Spring 이 하므로 호출부 변경은 없다.

## 어떻게 지켜지나

`GithubClientTest` (신규) — 최소 네 경우를 고정한다:

| 경우 | 왜 |
|---|---|
| 100건 페이지 뒤 빈 페이지 | 경계. 여기서 안 멈추면 무한 루프 |
| 100건 미만 단일 페이지 | 첫 페이지에서 끝나는 정상 경로 |
| 3페이지 연속 (100/100/37) | 저장된 커밋이 237건인가 |
| 2페이지째 500 | 부분 저장이 아니라 전체 롤백인가 |

`MockRestServiceServer` 가 요청 URI 도 검증하므로 `per_page`·`page` 파라미터가
실제로 나가는지도 같이 고정된다.

## 일반 규칙

포트를 그릴 때 물을 것: **"이 선 아래에 로직이 얼마나 있는가?"**
선 아래가 얇은 번역층이면 포트 더블로 충분하다. 선 아래에 **판단**이 있으면
(루프·재시도·조건 분기) 그 판단은 포트 더블로 영영 검증되지 않는다.
그때 선택지는 판단을 선 위로 올리거나, **선을 하나 더 아래에 긋는 것**뿐이다.
